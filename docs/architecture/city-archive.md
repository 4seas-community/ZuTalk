# 交到城的档案馆

定案 2026-11-13。城邦的居民在 ZuTalk 里登录一次，之后一场录音的各语言文字稿
可以交到那座城的档案馆，归在对应的活动和频道下。城的软件是另一个项目
（下文叫「城」）；ZuTalk 是它的一个不在浏览器里的客户端。

这是继加密链接、发送副本（[share-links.md](share-links.md)）之后第三个把
文字给出去的出口，也是唯一一个**公开、长期留存**的出口。

## 0. 负责人定下的四条

1. **居民登录，以本人的名义交。** 不给 ZuTalk 另开一个身份。登录在
   「设置 › 账号」，侧栏底部有一行指过去。
2. **只交文字。** 音频留在这台 Mac（见第 6 节）。
3. **每场录音开始前确认一次归到哪场活动。** 没有「记住以后自动发」的全局
   开关——[ARCHITECTURE.md](ARCHITECTURE.md) 要求远程处理绑定到明确的用户
   操作，这一次确认就是那个操作。
4. **活动多的时候翻城的日历和清单来选。**

## 1. 登录

城里没有账号密码，一个人就是一把 Ed25519 钥匙。登录用的是城现成的
「连接新设备」：

1. ZuTalk 生成一次性的房号和一把临时 P-256 钥匙，出码 `os:link:<房号>.<公钥>`。
2. 居民在已登录的设备上「市政厅 → 身份 → 连接新设备 → 扫码」，或粘贴这个码。
3. 两边用 ECDH 算出同一把 AES-GCM 钥匙和一个六位核对数，各自显示。
4. 居民在旧设备上确认数字一致，旧设备把身份封好，经服务器的
   `/relay/<房号>` 交过来。房号五分钟失效。

也可以直接填恢复密钥。

**交过来的是整把钥匙。** 城没有「只能交素材」的小钥匙，所以登录以后 ZuTalk
能做这个人在城里能做的任何事。ZuTalk 只用它签第 3 节列的那几种记录；界面上
在登录和退出两处写明这一点。

签名钥匙的种子存在 `Secrets/content-keys.json` 里单独的一项
（`city-identity`），和录音的内容密钥用同一个受限的存储，不进钥匙串、
UserDefaults、SQLite。登录的是谁、在哪座城记在 `city/account.json`
（目录 0700，文件 0600，先写临时文件再改名）。退出登录把这两样都删掉。
一台 Mac 一次登录一个人。

## 2. 选活动

- 活动列表从 `GET /hub/polis:<城>?kinds=ev/…` 读，按城的规则合出每场活动现在
  的标题、时间、地点、主办、记录员，读一次存在本机（`city/calendar.json`），
  断网时照样能选。主办删掉的、能审的人在策展里删掉的（`polis/trash`）、取消了
  的都不列：交到一场城里已经没有的活动，素材挂不到任何地方。
- 这份列表在真实的城里有一兆多。读的时候要压缩传，也不要素材的改动
  （`arc/edit`，大半是带图的链接预览）：会场的网络常常不好。频道因此按建的
  时候的名字列出。
- 首页开始录音的卡片上有一行「归到活动」，在「我在主持活动」打开时出现
  （[interface-layers.md](../product/interface-layers.md)）。只有一场活动在进行时
  自动选好；同时有几场时不替人选；点开是月历加当天清单。按下开始时这一行在
  屏幕上才算确认；不在屏幕上就不归、不交——自动选好的活动不能在没人看见的
  情况下被交出去。
- 主题在自己的设置里选一个频道，这个主题下的录音交到活动的同时也放进去。
- 归到哪记在本机 `city/filings.json`，录音中、录完以后都能改。

## 3. 交什么

一场录音对应城里的一段「录音」（`tape/take`），只是没有音频分段：

| ZuTalk | 城的记录 |
| --- | --- |
| 这场录音 | `tape/take`，指着活动 |
| 原文句子（时刻、时长、说话人） | `tape/text` |
| 每种语言的译文 | `tape/tr`，每句带原文的指纹，原文改了会被标成过时 |
| 说话人的名字（可关） | `tape/who` |
| 标记的位置（可关；不含笔记） | `tape/mark` |
| 录完了 | `tape/end` |
| 档案馆里的那一件 | `arc/block`，再用 `arc/connect` 连到活动和频道 |

记录用登录的那把钥匙签（Data Integrity `eddsa-jcs-2022`）。转录（`tape/*`）
只贴到活动的标签；档案馆里的那一件和它的连接，签的人是居民时再贴到城的
标签——档案馆的总览和主题的频道都从那里读。协议实现在 `crates/vt-city`，
它不依赖 ZuTalk 的任何别的 crate；它和城的代码对不对得上，由
`tools/city-interop/` 里的脚本拿城自己的代码来验（要一份城的检出，不进 CI）。

因为没有音频分段，城的页面上这件素材有转录稿、能切语言、有说话人和标记，
但没有波形，播放键按了没有反应。那是城的页面要改的地方。

不交：音频、笔记、标记旁写的字、AI 整理的段落、主题的专有词与背景。

## 4. 谁交得上

活动的标签只验签名，谁能往活动里放素材是读的那一端算的。所以 ZuTalk 在发
之前自己先查，照城的规则：

- 这场活动的主办、记录员；
- 这座城的协调者；
- **收进来的活动**（从别处的日历自动收入的，占城里日历的大半）归城管，城里
  能审的人——协调者和策展人——都算它的主办，他们指的记录员也算。

不在这几种里就不发，告诉他请主办把他加为记录员。交不上的东西不往公开日志里写。

谁能审只有城说得准：ZuTalk 向城的 `/p/<城>/vc` 挨个问签过收入活动、改过
收入活动的人，问过的记六小时。活动和这些判断只从**城的标签**读，不从活动
自己的标签读——城的服务器只让居民和它授权的那把收活动的钥匙往城的标签上写，
「这一条是能审的人签的」才有意义。发之前现读一遍，主办刚改过记录员也跟得上。

城那边「居民都能给活动交素材」的改动上线以后，这里要跟着放宽成：是居民就能交。

## 5. 什么时候交，失败了怎么办

- 停止录音不等上传。录音先存好，归了活动的那一场在本机标成「排队」，后台去
  交；交完出一条提示。
- 连不上城的服务器：留在「排队」，每两分钟、回到应用时、下次启动时再交。
  连不上不等于这台 Mac 没联网——到某一台服务器的路常常自己断一阵——界面上
  不这样说。读的请求没通会自己再试一次。
- 发之前现读一遍活动列表。那一场在城里已经没有了就不发，明说，请人换一场。
- 交上去以后那一场在城里被删了：城里看不到这件素材了。本机下一次读到活动
  列表时把这场录音标成「活动在城里已删除」，不让「已交」和城里的样子对不上。
- 每场录音交到哪一步，在录音自己身上、录音列表里、设置的清单里用同一套
  说法：未交、已选活动还没交、正在交、排队中、已交、已交但改过字、活动在城里
  已删除、没交上、已撤下。主窗口的侧栏在有排队或没交上的录音时提一句。
- 交上去以后在 ZuTalk 改了字：不自动同步。录音的共享面板里写「你改了 N 句」，
  人按「更新」才发（`tape/fix` 加重新签的译文）。每次更新都是一次对外发送。
- 撤下：签 `arc/mark { to: "drop" }`，素材从档案馆页面消失。**已经交上去的
  转录记录在城的日志里删不掉**，界面上照实写。

## 6. 音频不外传

这条路只碰文字。`scripts/test_share_no_audio_gate.sh` 第 6 层守着：

- `crates/vt-city` 不依赖 `vt-audio`、`vt-crypto`；
- `crates/vt-ffi/src/city_api.rs` 不引用音频解密、PCM 类型，也不发 `tape/part`、
  不调 `/files/`；
- App 里 `City*.swift` 不碰音频导出。

## 7. 和加密链接的区别

| | 加密链接 | 档案馆 |
| --- | --- | --- |
| 谁看得到 | 拿到链接的人 | 公开（或按活动的可见范围） |
| 留多久 | 24 小时 | 一直留着 |
| 服务器看得到内容吗 | 看不到 | 看得到 |
| 收得回吗 | 撤销即删 | 只能从页面撤下 |

界面在共享面板里把这几条写在「档案馆」那一段上。
