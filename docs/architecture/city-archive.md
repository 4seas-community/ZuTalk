# 交到城的档案馆

定案 2026-11-13；2026-11-14 改了交什么（第 0 节）。城邦的居民在 ZuTalk 里登录
一次，之后一场录音的各语言文字稿、连同它的音频，可以交到那座城的档案馆，归在
对应的活动和频道下。城的软件是另一个项目（下文叫「城」）；ZuTalk 是它的一个
不在浏览器里的客户端。

这是继加密链接、发送副本（[share-links.md](share-links.md)）之后第三个把
内容给出去的出口，也是唯一一个**公开、长期留存**的出口，唯一一个**能带音频**
的出口。

## 0. 负责人定下的

2026-11-13 定了四条：

1. **居民登录，以本人的名义交。** 不给 ZuTalk 另开一个身份。登录在
   「设置 › 账号」，侧栏底部有一行指过去。
2. **只交文字。** 音频留在这台 Mac。——**2026-11-14 改了，见下面第 5 条。**
3. **每场录音开始前确认一次归到哪场活动。** 没有「记住以后自动发」的全局
   开关——[ARCHITECTURE.md](ARCHITECTURE.md) 要求远程处理绑定到明确的用户
   操作，这一次确认就是那个操作。
4. **活动多的时候翻城的日历和清单来选。**

2026-11-14 改了两条规矩，又定了两件事：

5. **标记不交，录音可以交。** 原话：「不给标记数据，录音可以给。」
   - 标记——位置和旁边写的字——从此都不交。0.8.0–0.8.2 交过标记的位置，那些
     记录留在城的日志里删不掉；这一版起一条都不再签。
   - 音频可以交到档案馆。**只有这一条路可以**：加密链接、发送副本、设备
     同步、附近递稿与直播、加密备份照旧不带音频，一点没松。
6. **音频默认交。** 问过：交上去的音频是公开的、删不掉（第 7 节），知道这一点
   还要不要默认就交。选的是：要，默认开。设置里可以关；开着的时候，某一场也
   可以单独不交。
7. **升级的人不另加一道确认。** 0.8.0–0.8.2 的界面上写过「音频留在这台
   Mac」，所以想过给那时已经登录的人加一道闸：看过一次说明、点过头，才开始交
   音频。负责人不要这道闸，原话：「升級後先看到一次提示，不用加这个保护。
   因为只有主持人，并且做了多次操作，才交了。」所以新登录的和早就登录的一样：
   设置开着、这一场没单独关，就交。core 里没有「确认过没有」这回事。

## 1. 登录

城里没有账号密码，一个人就是一把 Ed25519 钥匙。登录用的是城现成的
「连接新设备」：

1. ZuTalk 生成一次性的房号和一把临时 P-256 钥匙，出码 `os:link:<房号>.<公钥>`。
2. 居民在已登录的设备上「市政厅 → 身份 → 连接新设备 → 扫码」，或粘贴这个码。
3. 两边用 ECDH 算出同一把 AES-GCM 钥匙和一个六位核对数，各自显示。
4. 居民在旧设备上确认数字一致，旧设备把身份封好，经服务器的
   `/relay/<房号>` 交过来。房号五分钟失效。

也可以直接填恢复密钥。

**交过来的是整把钥匙。** 城没有「只能交素材」的小钥匙，所以登录以后 ZuTalk
能做这个人在城里能做的任何事。ZuTalk 只用它签第 3 节列的那几种记录；界面上
在登录和退出两处写明这一点。登录的地方同时写明：交到档案馆的包括音频，默认
开着，交上去撤不回来。

签名钥匙的种子存在 `Secrets/content-keys.json` 里单独的一项
（`city-identity`），和录音的内容密钥用同一个受限的存储，不进钥匙串、
UserDefaults、SQLite。登录的是谁、在哪座城记在 `city/account.json`
（目录 0700，文件 0600，先写临时文件再改名）。退出登录把这两样都删掉。
一台 Mac 一次登录一个人。

## 2. 选活动

- 活动列表从 `GET /hub/polis:<城>?kinds=ev/…` 读，按城的规则合出每场活动现在
  的标题、时间、地点、主办、记录员，读一次存在本机（`city/calendar.json`），
  断网时照样能选。主办删掉的、能审的人在策展里删掉的（`polis/trash`）、取消了
  的都不列：交到一场城里已经没有的活动，素材挂不到任何地方。
- 这份列表在真实的城里有一兆多。读的时候要压缩传，也不要素材的改动
  （`arc/edit`，大半是带图的链接预览）：会场的网络常常不好。频道因此按建的
  时候的名字列出。
- 首页开始录音的卡片上有一行「归到活动」，在「我在主持活动」打开时出现
  （[interface-layers.md](../product/interface-layers.md)）。只有一场活动在进行时
  自动选好；同时有几场时不替人选；点开是月历加当天清单。按下开始时这一行在
  屏幕上才算确认；不在屏幕上就不归、不交——自动选好的活动不能在没人看见的
  情况下被交出去。
- 归了活动的这一场可以单独选「不交音频」（`city_set_session_audio`）。这个选择
  跟着这场录音，换一场活动也不会被悄悄改回去。设置是总开关：设置里关着的
  时候，单场说「要」也不交。
- 主题在自己的设置里选一个频道，这个主题下的录音交到活动的同时也放进去。
- 归到哪记在本机 `city/filings.json`，录音中、录完以后都能改。
- **录完以后再交**（0.8.4）。负责人的原话：「以及录制后的素材，有地方可以提交给
  活动作为素材。」一场录好的录音自己身上有「交到活动」，三处入口打开同一张表
  （`Pages/CityFilingSheet.swift`）：
  - 停止以后那张卡上「分享」后面的一颗胶囊；
  - 录音页标签栏上——还没归过活动是这颗胶囊，归过以后是档案馆的状态；
  - 录音的「⋯」菜单里：它自己的页面上、首页和主题里它的那一行上。

  谁看得到，是一个函数说了算（`CityFilingEntry.resolve`）：没登录城，哪里都
  没有；正在录的那一场没有（它归到哪在录音条上）；页面上的两处是第一层，「主持
  活动」开着才摆出入口，可已经归了活动的录音不管开关都显示状态；菜单是第二层，
  登录了就有。那张表里只有分享面板里原样的「档案馆」一段——选活动、交、这一场
  交不交音频、文字和音频各自的状态、更新、撤下，和它那几处 ⓘ；分享面板里那
  一段照旧在。没在开始前归活动的录音以前只能从「⋯ → 分享」里找到这一段。

## 3. 交什么

一场录音对应城里的一段「录音」（`tape/take`）：

| ZuTalk | 城的记录 |
| --- | --- |
| 这场录音 | `tape/take`，指着活动 |
| 原文句子（时刻、时长、说话人） | `tape/text` |
| 每种语言的译文 | `tape/tr`，每句带原文的指纹，原文改了会被标成过时 |
| 说话人的名字（可关） | `tape/who` |
| 音频，每 5 分钟一段（默认交；设置里可关，单场可关） | 每段一条 `tape/part`，指着这段录音：段号、文件的指纹、大小、起点、时长、类型、每秒一个 0–9 的音量；文件本身 `PUT /files/<指纹>` |
| 录完了 | `tape/end` |
| 档案馆里的那一件 | `arc/block`，再用 `arc/connect` 连到活动和频道 |

记录用登录的那把钥匙签（Data Integrity `eddsa-jcs-2022`）。转录和音频分段
（`tape/*`）只贴到活动的标签；档案馆里的那一件和它的连接，签的人是居民时再贴
到城的标签——档案馆的总览和主题的频道都从那里读。协议实现在 `crates/vt-city`，
它不依赖 ZuTalk 的任何别的 crate；它和城的代码对不对得上，由
`tools/city-interop/` 里的脚本拿城自己的代码来验（要一份城的检出，不进 CI）。

**不交：标记（位置和旁边写的字）、笔记、AI 整理的段落、主题的专有词与背景。**
城的协议里有标重点的记录（`tape/mark`），`vt-city` 里没有签它的函数，
`city_api.rs` 不读标记。

文字先交，音频跟在后面一段段交，两件事各算各的（第 5 节）。带了音频的，城的
页面上这件素材有波形、能播放、能拖动；没带的（设置关着、这一场单独关了、城
没收下）和以前一样：有转录稿、能切语言、有说话人，没有波形，播放键按了没有
反应。

### 音频怎么交

- **切段和编码在 App。** App 把这场录音的音频每 300 000 毫秒切一段（最后一段
  短），每段导出成一个能单独播放的 AAC `.m4a`，连同它在录音时间线上的起点、
  长度和每秒的音量交给 core。时间线和转录句子的时刻是同一个钟。
- **core 只经手编好码的文件。** 它读文件的字节、算 SHA-256、签记录、上传；
  不解密录音，不认得采样。开头不是 MPEG-4 的文件不收：记录里写的类型是
  `audio/mp4`，交上去改不了。
- **顺序是城定的。** 先把这一段的 `tape/part`（连同它指着的那条 `tape/take`，
  再贴一遍）贴到活动的标签，再 `PUT /files/<指纹>`，一个请求、写明长度、不带
  任何凭据。反过来服务器回 403：它只收「认领过」的文件，认领就是标签上那条
  写着这个指纹和大小、由这段录音的作者签的 `tape/part`。
- **一段最多 16 MiB**，超过的在发之前就拦下。一个人一天往城里放的有上限
  （2 GiB，按 UTC 的一天算），到了回 429 和「多久以后再来」。服务器盘不够时
  回 507。
- **断了接着交。** 每一段签之前先记进这场录音的细账
  （`city/sent-<录音>.json`）：指纹、大小、起止、签的时刻，之后再记上记录贴
  上去没有、文件传完没有。记录贴出去、文件还没传完就断了（一段几兆，会场的网
  常这样），下一次：
  - 字节没变，签出来的是同一条记录，城里不会多一条；城里已经有这些字节就不
    再传；
  - 字节变了（重新导出的 `.m4a` 不保证逐字节相同）：上一条记录贴上去过的话，
    先问它的文件是不是其实已经在城里——在，这一段就算交了，不传第二份。不在，
    新的一条记录签的时刻写在旧的那条**前一毫秒**。城对每个段号只认它最先遇到
    的那一条（按签的时刻排），这样它放的是真有文件的那一条；
  - 已经交了的段不再联网。

  「这一段交了」只在两件事都成了以后才记：活动的标签收下了记录，文件服务器
  上有那个文件。
- **以前只交了文字的录音**（0.8.0–0.8.2 交的，或者当时关着音频）不会自己补交
  音频，等人开口；开了口走的是同一条路。那时交上去的 `tape/take` 细账里没留，
  用到时从活动的标签上取回来。

## 4. 谁交得上

活动的标签只验签名，谁能往活动里放素材是读的那一端算的。所以 ZuTalk 在发
之前自己先查，照城的规则：

- 这场活动的主办、记录员；
- 这座城的协调者；
- **收进来的活动**（从别处的日历自动收入的，占城里日历的大半）归城管，城里
  能审的人——协调者和策展人——都算它的主办，他们指的记录员也算。

不在这几种里就不发，告诉他请主办把他加为记录员。交不上的东西不往公开日志里写。

谁能审只有城说得准：ZuTalk 向城的 `/p/<城>/vc` 挨个问签过收入活动、改过
收入活动的人，问过的记六小时。活动和这些判断只从**城的标签**读，不从活动
自己的标签读——城的服务器只让居民和它授权的那把收活动的钥匙往城的标签上写，
「这一条是能审的人签的」才有意义。发之前现读一遍，主办刚改过记录员也跟得上。

城那边「居民都能给活动交素材」的改动上线以后，这里要跟着放宽成：是居民就能交。

**音频多一道，由城的文件服务器在收文件时定**：录的人要住在这座城里；并且
这场活动是居民建的，或者录的人是它的主办、记录员。文字交得上的人里，只有
「不是居民的主办、记录员」这一种音频交不上。登录时还不是居民的，ZuTalk 在签
第一段之前现问一遍名分；还不是，就一条 `tape/part` 都不签——认领不上的分段
贴出去，只会在公开的日志里留下一段放不出来的录音和它每秒的音量。别的情形
ZuTalk 事先算不出来，以服务器的回话为准：403 就停在那一段，这场录音是
「已交，音频没收下」。

## 5. 什么时候交，失败了怎么办

- 停止录音不等上传。录音先存好，归了活动的那一场在本机标成「排队」，后台去
  交；交完出一条提示。
- **先文字，后音频。** 文字交上去的那一刻设置和这一场都要音频，音频就算
  「该交」，App 接着一段段导出、上传；启动时、网络回来时照
  `city_pending_audio_sessions` 接着交。
- **文字和音频各算各的。** 音频没交成不改文字那一路的状态：这场录音还是
  「已交」，旁边写音频交到第几段、为什么停了。原因分得开，因为人要做的事
  不一样：

  | 城的回话 | 这一头记成 | 之后 |
  | --- | --- | --- |
  | 没连上、超时 | `city.error.offline` | 自己再试 |
  | 500、400（字节在路上坏了） | `city.error.server` | 自己再试 |
  | 507 盘满了 | `city.error.audio_server_full` | 自己再试 |
  | 429 今天放得太多 | `city.error.audio_daily_cap`，记下什么时候能再来 | 到时候自己再试，之前不碰它 |
  | 403 没有认领 | `city.error.audio_refused` | 不再自己试，等人来看 |
  | 413 一段太大 | `city.error.audio_too_big` | 不再自己试 |

- 连不上城的服务器：留在「排队」，每两分钟、回到应用时、下次启动时再交。
  连不上不等于这台 Mac 没联网——到某一台服务器的路常常自己断一阵——界面上
  不这样说。读的请求没通会自己再试一次。上传一段音频给的时间和城的服务器
  给的一样长：文件大小 ÷ 16 KiB/s，再加 60 秒。
- 发之前现读一遍活动列表。那一场在城里已经没有了就不发，明说，请人换一场。
- 交上去以后那一场在城里被删了：城里看不到这件素材了。本机下一次读到活动
  列表时把这场录音标成「活动在城里已删除」，不让「已交」和城里的样子对不上。
- 每场录音交到哪一步，在录音自己身上、录音列表里、设置的清单里用同一套
  说法：未交、已选活动还没交、正在交、排队中、已交、已交但改过字、活动在城里
  已删除、没交上、已撤下。已交的再分：没带音频、音频在交（第几段）、音频交完、
  音频没收下。主窗口的侧栏在有排队或没交上的录音时提一句。
- 交上去以后在 ZuTalk 改了字：不自动同步。录音的共享面板里写「你改了 N 句」，
  人按「更新」才发（`tape/fix` 加重新签的译文）。每次更新都是一次对外发送。
  改字不动音频。
- 撤下：签 `arc/mark { to: "drop" }`，素材从档案馆页面消失。**已经交上去的
  转录记录在城的日志里删不掉，已经交上去的音频在城的服务器上也删不掉**
  （第 7 节），界面上照实写，交了几段照实留着。撤下以后再交是另一段录音，
  音频从头算。

## 6. 音频从哪里离开这台 Mac

只有这一条路，只在下面四条都成立的时候，一场一场地算：

1. 登录着——音频以本人的名义交；
2. 这一场的文字稿已经交上去——音频挂在那段录音上；
3. 设置里「连音频一起交」开着（默认开；0.8.0–0.8.2 留下的设置里没有这一项，
   读进来也是开）；
4. 这一场没有被单独设成不交音频。

这四条写在一个函数里（`city_api.rs` 的 `audio_clearance`）。签音频分段、传
文件在全仓库只有一个函数（`city_send_part`），它要拿着 `audio_clearance` 给的
凭据才调得动。缺一条，什么都不读、不签、不传。

加密链接、发送副本、设备同步、附近递稿与直播、加密备份**永远不带音频**：
它们够不到 `vt-city`，也就够不到传文件的函数。

`scripts/test_share_no_audio_gate.sh` 第 6 层守着（前五层管别的出口，没动）：

- `crates/vt-city` 在依赖图上够不到 `vt-audio`、`vt-crypto`，源码里不提录音的
  密文、钥匙、采样——它经手的只是别人编好码的文件；
- `crates/vt-ffi/src/city_api.rs` 不引用音频解密、PCM 类型，密钥库只取登录的
  那一把签名钥匙；
- `audio_clearance` 里四条一条不少；凭据只有它造得出来；`build_part`、
  `file_put` 只在 `city_send_part` 里各出现一次；`city_send_part` 只有一处
  调用，而且先过闸；
- 别的 crate 不依赖 `vt-city`，`vt-ffi` 里别的模块不引用它；
- `vt-city` 里没有 `tape/mark`，`city_api.rs` 不读标记；
- App 里为档案馆导出音频只许在 `CityAudioExport*.swift` 里做，而且要先问
  `cityAudioPlan`；别的 `City*.swift` 不碰音频；`cityFileAudioPart` 只许
  `City*.swift` 调。

## 7. 交上去就撤不回来的

登录、设置、每一次要交之前的地方都要让人看得到这一节说的事。

- **音频是公开的，凭指纹谁都取得到。** 城的文件服务器不问来的人是谁、不看
  活动的可见范围：`GET /files/<指纹>` 就给。指纹写在那条 `tape/part` 里，
  活动的标签谁都读得到。
- **取走的人可以一直留着。** 服务器让浏览器和中间的缓存把它当成永远不变的
  东西存下来。
- **没有删除。** 城的协议里没有删文件的记录，也没有删文件的接口。撤下
  （`arc/mark { to: "drop" }`）只让档案馆里那一件从页面上消失；`tape/*` 记录
  和文件都留着。关掉设置、把这一场改成不交、退出登录，都只管以后，不管已经
  交上去的。
- **城可以拿存着的音频再转写。** 这一场的主办、记录员和城的协调者能在那件
  素材上按「补转写」，城的服务器把音频段交给它自己的转写服务。
- **每秒的音量也是公开的。** 它写在记录里，和文字一样留在城的日志里。
- 文字这一路照旧：转录、译文、说话人的名字交上去以后留在城的日志里，删不掉；
  0.8.0–0.8.2 交过的标记位置也是。

## 8. 和加密链接的区别

| | 加密链接 | 档案馆 |
| --- | --- | --- |
| 带不带音频 | 不带 | 默认带（设置里可关，单场可关） |
| 带不带标记 | —— | 不带 |
| 谁看得到 | 拿到链接的人 | 公开（或按活动的可见范围）；音频凭指纹谁都取得到 |
| 留多久 | 24 小时 | 一直留着 |
| 服务器看得到内容吗 | 看不到 | 看得到 |
| 收得回吗 | 撤销即删 | 只能从页面撤下；文字记录和音频都留着 |

界面在共享面板里把这几条写在「档案馆」那一段上。
