# 本地优先：设备之间直接同步（iroh）

定案 2026-09-29。负责人要求把 iroh 集成回来做本地优先，四项能力按顺序分期：

1. **自己的多台 Mac 同步**（本文第一期）
2. 和其他 ZuTalk 用户协作一个主题
3. 同一网络内直接共享（不经字幕服务器）
4. 加密备份到自己的另一台设备

**音频永远不同步。** 这是负责人的明确选择，不是默认值，没有开关。浏览器观众仍走加密链接
（[share-links.md](share-links.md)），iroh 只用于 ZuTalk 与 ZuTalk 之间。

## 0. 从现有存储推出来的几条硬约束

- **界面读的是 SQLite，不是 Loro。** 实时转录稿的句子、各语言栏、订正都在 SQLite
  （`realtime_utterances`、`_variants`、`_overrides`），T2 文档只是它的投影。只同步 Loro
  文档，另一台 Mac 上什么都看不到。
- **主题的三份文档编号每台 Mac 各自随机**（`notebook_tabs.doc_id`）。同名主题在两台 Mac
  上是两份不相干的文档。每场录音的笔记例外：编号由录音 id 推出，天然一致。
- **精修稿的用户编辑只存在 Loro 里**（主题的精修稿文档，按录音分段）。
- **「未归入主题」每台 Mac 各有一个随机 id**，靠保留标题找回。
- **没有变更日志。** 大部分表有 `updated_at`，`session_records` 等几张没有。
- 音频、音频密钥、「专有词与背景」资料的密钥都只在本机（`Secrets/content-keys.json`），
  路径是本机绝对路径。

## 1. 总体做法：同步事实，本地投影

同步的单位是 **Loro 文档**：CRDT 自带合并、版本向量与增量导出，上一代点对点已经验证过
「版本向量交换 → 导出差量 → 导入」这条路。分两类：

**A. 同步文档（新增，专为同步而设）**——SQLite 事实的可合并表示。收到后由「物化器」写回
SQLite，再由本机既有的投影流水线把它投进本机的 T2 文档：

- `library`（每个设备组一份）：
  - 主题：id、标题、建立时间、删除时间、三份文档的编号、录音设置（语言等）
  - 录音归属：录音 id → 主题 id（「未归入」用逻辑 id `unfiled`，各机映射到本机的那个）
  - 回收站状态：录音 id → 放入时间 / 空
  - 永久删除墓碑：录音 id → 删除时间（任何一台删了，所有设备都删）
  - 人名名单：id → 名字 / 删除时间
- `recording/<录音 id>`（每场录音一份）：
  - 元数据：建立时间、类型、状态、时长、语言、来源设备、来源信息（provider/model）
  - 标题（后写者胜）
  - 实时转录的**定稿**句子与各语言栏（只有录音那台写，写入即不变）
  - 订正：句子 × 语言 → 文字（后写者胜）
  - 说话人：标签、名字、关联的人名
  - 标记：时间范围、备注、删除时间
  - 精修结果（provider tokens，写入即不变）

**B. 直接同步的既有文档**——编号在设备组内一致，直接作为 CRDT 同步：

- 每场录音的笔记（编号由录音 id 推出）
- 主题笔记（编号随 `library` 里的主题一起定下）
- 主题的精修稿文档（同上）。**只有录音那台 Mac 投影它的精修段落**，其他设备只收不投，
  否则两台同时渲染同一段，合并后就是两份。

**不同步**：音频与音频密钥、录音中的实时预览、任务队列、云端转写的回收台账、共享链接台账、
设备本地的计数器与投影水位、「专有词与背景」（资料用本机密钥加密；第二期再定怎么带）、
各机的界面偏好。

## 2. 设备组与配对

- 每台 Mac 有一个设备身份（iroh `SecretKey`，存在 `Secrets/`，0600）。
- 设备组有一个组密钥（随机 32 字节）和一份**签名的设备名单**（设备 id、名字、加入时间、
  移除时间）。名单本身也是一份同步文档，只接受名单内设备签名的修改。
- 配对：在已有设备上点「添加 Mac」，显示一个短期有效（10 分钟）的配对码（含已有设备的地址
  与一次性密钥）；新 Mac 上输入或粘贴。同一网络下，新 Mac 会直接出现在已有设备的「附近」
  列表里，两边核对同一串数字即可。
- 新 Mac 加入时如果已有自己的数据：它的主题与录音并入设备组；它的「未归入主题」里的录音
  移进设备组的那个「未归入主题」（用现成的移动逻辑）。
- 移除设备：从名单上划掉，其他设备不再和它同步；它自己留着已经同步到的数据。

## 3. 传输

- iroh 1.3.0，`presets::Minimal`（不把地址发布到公共目录）；自建中继
  `zulangue-relay.exe.xyz`；同一网络用 mDNS 发现。
- 每对设备一条连接，所有文档复用：先交换各自的文档摘要（文档 id → 版本向量的哈希），
  只对不一致的文档交换版本向量与差量；本机改动实时推送；断线自动重连（在传输层，不靠界面
  轮询）；重连后先对摘要。
- 两边都会拨号：设备 id 小的一方先拨，大的一方等 3 秒没见到连接再拨（对方可能在退避，
  或还守着一条已断的旧连接）。两条连接建立时间相差不到 3 秒算同时拨出，两边都留 id 小的
  一方拨出的那条；否则新的换掉旧的——对方肯拨过来，说明它那头已经没有可用连接。
- 只拉不推：每台设备按对方的摘要要自己缺的，对方按请求方的版本导出差量。每个请求都有
  应答（没有可给的也回空的末块），反熵每 60 秒一轮完整摘要。
- 编码用 postcard，按文档分块，单块上限 1 MiB；一个大文档的追赶分多块发。
- 只接受名单内设备的连接（QUIC 已认证对方 id，直接对名单）。
- **中继门禁要改**：现在只放行登记过邀请码的设备，没有邀请码的人跨网络就同步不了。第一期
  改为放行所有设备，靠中继自带的速率限制防滥用（流量本就端到端加密，只有文字）。

## 4. 冲突与删除

- 文字（笔记、精修稿、订正）：Loro 合并。
- 标量（标题、归属、回收站状态、名字）：后写者胜（Loro Map 的 Lamport 时序）。
- 永久删除：墓碑优先于一切——任何设备收到墓碑就执行本机的永久删除，之后再收到这场录音的
  任何内容都丢弃。
- 删除主题：录音移到「未归入主题」，主题标记删除；和单机行为一致。

## 5. 界面（第一期）

- 设置 › 设备：本机名字、已配对的 Mac（在线/上次同步时间）、添加 Mac、移除。
- 录音行与录音页：来自另一台 Mac 的录音标注「在 X 上录的」；没有音频时，「精修转录」
  「导出音频」这类需要音频的动作说明「音频在 X 上」。
- 录音中的那一场：录完才出现在其他设备上。

## 6. 分步

1. `vt-sync` 包：设备身份、设备组、配对码、端点、连接管理、文档同步协议；用假文档在
   进程内测（不走中继、不开 mDNS）。
2. 同步文档与物化器：`library`、`recording/<id>`；本机改动写入同步文档的钩子；两个核心
   在同一进程里互相同步的集成测试。
3. 既有文档的同步：录音笔记、主题笔记、精修稿（只由录音那台投影）。
4. 核心接口与界面：设置 › 设备、配对流程、录音来源标注。
5. 中继门禁调整与部署；「音频不外传」门禁扩展到 `vt-sync`。

## 7. 音频不外传

`vt-sync` 在依赖图上够不到 `vt-audio` 与 `vt-crypto` 的音频接口；同步文档的字段是封闭
列表，没有音频、音频路径、密钥引用。`scripts/test_share_no_audio_gate.sh` 扩展到这个包。
